Structural Break Primer

The background you need for online change detection, from the statistics the baseline relies on up to the research-level methods. Each section gives the key ideas, the formulas, and where they come in for this challenge.

The setup in one picture

τ
Break position, 0-indexed within the online segment. None in about half of the series.
yₜ
1 if a break exists and t ≥ τ, else 0. The step t = τ already counts as post-break.
sₜ
What you output after seeing point t: how confident you are that the break has already happened.
TS-AUC
At each step, ranks all series by sₜ against yₜ (an AUC), then averages those AUCs, weighted by n_pos·n_neg.

§1

Time-series basics

Core
  • Stationary means the statistical behaviour doesn't change over time. The historical segment is your stationary reference: "normal" for this series.
  • Moments. Mean (level), variance (spread), skewness (asymmetry), kurtosis (how heavy the tails are).
  • Autocorrelation ρₖ. How much xₜ resembles xₜ₋ₖ. Real series are rarely independent, and autocorrelated noise makes naive tests raise false alarms.
  • AR(p) model and residuals. Fit xₜ as a linear function of its last p values on the historical segment. The residuals are close to independent, so you can monitor them with simple tests ("whitening").
  • Volatility clustering (GARCH). In financial series, variance moves around on its own without any permanent break. This can trigger a variance detector by mistake.
zₜ  = (xₜ − μ_H) / σ_H          # standardise by HISTORY, not by online data
ρₖ  = Cov(xₜ, xₜ₋ₖ) / Var(x)
AR(1):  xₜ − μ = φ(xₜ₋₁ − μ) + εₜ
resid:  eₜ = (xₜ − μ) − φ̂(xₜ₋₁ − μ)  # ≈ iid if no break

Used forEvery feature is measured relative to the historical segment, usually after standardising or whitening.

§2

Kinds of structural break

Core
Break typeWhat changesCheap running signal
Mean shiftLevelRunning / EWMA mean of zₜ
Variance changeSpreadMean of zₜ² (≈ 1 if unchanged)
Distribution shapeSkew, tails; mean and variance can stay the sameTail fractions beyond ±2σ/±3σ, KS distance, quantile-bin counts
DependenceAutocorrelation / dynamicsOnline lag-1 product zₜzₜ₋₁ vs historical ρ₁; AR-residual CUSUM
  • Small shifts take many points to detect. The best possible detection delay is about log(ARL) / KL, where KL measures how different the before and after distributions are. For a mean shift of δ standard deviations, KL = δ²/2, so halving the shift means roughly four times the delay.
  • Each series has at most one break, and it's permanent. Once the data has changed, it stays changed.

Used forChoosing which features to compute, and creating synthetic training breaks (§11).

§3

Two-sample hypothesis tests

Core

Null hypothesis H₀: the online points come from the same process as the historical ones.

  • Mean: z-test or Welch t-test, or Mann–Whitney if you use ranks.
  • Variance: F-test (assumes normality) or Levene (robust).
  • Whole distribution: Kolmogorov–Smirnov (KS), or Anderson–Darling, which is more sensitive in the tails.
  • Likelihood ratio: the most powerful test when both distributions are known (Neyman–Pearson lemma). CUSUM is built from it.
Λ = f₁(x) / f₀(x)              # likelihood ratio, use log Λ
D = supₓ | F̂_online(x) − F̂_hist(x) |   # KS statistic

TrapTesting "history vs all online points so far" weakens after a late break, because the pre-break online points dilute the signal. Use sliding windows or maximise over possible split points (§4).

TrapRunning a test at every step is repeated testing, so the p-values are no longer valid. That's fine here: TS-AUC only needs a good ranking, not calibrated p-values.

§4

Sequential detection

Core
  • Shewhart chart. Raises an alarm when a single |zₜ| > 3. Only catches large jumps.
  • EWMA. A moving average whose memory decays exponentially (the baseline uses this). Catches moderate shifts.
  • CUSUM (Page, 1954). Adds up evidence and resets at zero. The standard tool. Run one for each direction, and one on z² for variance.
  • Page–Hinkley. A CUSUM variant that uses a running mean.
  • GLR / scan. Maximises over the unknown change time, so you don't need to know the shift size.
  • Shiryaev–Roberts. Sums over possible change times instead of maximising. Closely related to the Bayesian approach.
CUSUM up:   S⁺ₜ = max(0, S⁺ₜ₋₁ + zₜ − k)
CUSUM down: S⁻ₜ = max(0, S⁻ₜ₋₁ − zₜ − k)
variance:   Vₜ  = max(0, Vₜ₋₁ + (zₜ² − 1) − k)
LR-CUSUM:   Sₜ  = max(0, Sₜ₋₁ + log Λ(xₜ))
GLR (mean): Gₜ  = max_j (Σᵢ₌ⱼᵗ zᵢ)² / (2(t−j+1))
SR:         Rₜ  = (1 + Rₜ₋₁) · Λ(xₜ)
# k ≈ half the shift you want to catch, in σ units
  • ARL is the average run length before a false alarm. EDD is the expected detection delay. Classic detection theory trades one against the other.
  • Here you don't need an alarm threshold. The statistic's value is your score, or a feature for the model. Any increasing function (1−e^{−S}, tanh, sigmoid) gives the same per-step ranking, and so the same TS-AUC.
§5

Streaming computation

Core
  • The test data is 10,000 series × up to 1,000 steps, so up to about 10 million updates. Each step should take microseconds. A full scipy test at every step is too slow.
  • Precompute from history once: μ_H, σ_H, quantiles, AR coefficients, a sorted array for ranking new points (bisect / np.searchsorted).
  • Update in O(1): running sums Σz, Σz², Σz³, Σz⁴; lag products Σzₜzₜ₋₁; EWMAs at a few decay rates; CUSUMs.
  • Sliding windows: a collections.deque(maxlen=w); add the new value and subtract the one that drops out.
  • Plain Python floats beat numpy on single numbers, because numpy has a fixed per-call overhead.
Welford (stable running mean/var):
  n += 1;  d = x − m;  m += d / n;  M2 += d · (x − m)
  var = M2 / (n − 1)
EWMA:   mₜ = (1 − α)·mₜ₋₁ + α·xₜ
window: S ← S + x_new − x_dropped

TrapFeatures must use only points up to t. Vectorised training code (centred rolling windows, shift(-1)) can quietly use future values. Compute training features with the same streaming code you use at inference.

§6

The metric: AUC and TS-AUC

Core
  • AUC is the probability that a randomly chosen positive gets a higher score than a randomly chosen negative (ties count ½). 0.5 is chance. It ignores the scale of the scores, only their order.
  • TS-AUC computes an AUC separately at each online step t, across all series still running at t.
TS-AUC = Σₜ wₜ · AUCₜ / Σₜ wₜ,   wₜ = n_pos(t) · n_neg(t)
  • Scores are only compared across series at the same t. Offsets between different steps don't matter.
  • A score that depends only on t (for example t/T) gets exactly 0.5.
  • Steps with plenty of both classes carry the most weight. The first few steps, when almost no breaks have happened, contribute little.
  • Detecting early pays off: from τ onward, each step where a broken series ranks below unbroken ones costs you.

Used forLocal evaluation, and designing the training objective (§7).

§7

Supervised learning setup

Core
  • One row per (series, step), with label y = 1[τ is not None and t ≥ τ]. Include t as a feature so the model can learn how evidence builds up over time.
  • That's millions of rows, so subsample steps for training (for example every 5th step, or random steps per series).
  • Split folds by series (GroupKFold). Rows from the same series are near-copies, so a random split leaks and inflates the CV score.
  • Match the objective to the metric. Either use binary classification and choose the model by local TS-AUC, or use LightGBM lambdarank with each step t as a query group, which directly optimises ranking within each step.
  • Gradient boosting (LightGBM / XGBoost): the main settings are num_leaves, learning_rate, number of trees with early stopping, and min_data_in_leaf. Prune features with SHAP or importance scores.
  • Save the model with joblib in train() and load it in infer().

TrapFor deterministic output, set seed, deterministic=True and a fixed num_threads in LightGBM.

§8

Python and platform mechanics

Core
  • Generators. infer() runs one bare yield to signal it's ready, then yields exactly one float per online point, in order. Your per-series state lives in local variables between yields.
  • x_online can only be iterated once, and you can't take len() of it. You don't know how long the series is.
  • Determinism: rerunning must reproduce your output to within 1e-8. Fix all seeds, never break ties randomly, and keep the order of operations fixed.
  • Parallelism: INFER_PARALLELISM = n runs separate processes, each with its own share of the series. Wrap BLAS calls in threadpoolctl.threadpool_limits(1) and don't write files inside infer().
  • Local loop: crunch_tools.test() writes prediction/prediction.parquet; labels for scoring locally are in data/y_test.reduced.parquet.
  • Check Resources → Whitelisted Libraries before depending on any package.
§9

Bayesian online change-point detection

Advanced
  • Tracks the run length rₜ, the time since the last change, as a probability distribution, updated after every point (Adams & MacKay, 2007).
  • The hazard H is the prior probability of a change at each step. Here about half the series break somewhere in the online segment, so set H around 0.5 / typical online length and tune it.
  • Each run length has a predictive model π(x | run). A Gaussian with a conjugate Normal-Gamma prior is the classic choice. Learn the "no change yet" model from the historical segment.
  • Score = 1 − (probability that the current run started back in the historical segment). That is a direct estimate of P(τ ≤ t).
  • The cost is O(t) per step, or O(K) if you keep only the K most likely run lengths.
grow:   P(rₜ = r+1) ∝ P(rₜ₋₁ = r) · π(xₜ | r) · (1 − H)
change: P(rₜ = 0)   ∝ Σᵣ P(rₜ₋₁ = r) · π(xₜ | r) · H
normalise over all r after each step
§10

Distribution-free monitors

Advanced

Kernel / MMD

  • The Maximum Mean Discrepancy (MMD) measures the distance between two distributions using a similarity kernel. It reacts to any kind of distribution change.
  • Online kernel CUSUM compares blocks of recent points against blocks sampled from the history, at a fixed cost per step.
k(x,y) = exp(−(x−y)² / 2ℓ²)
MMD² = E k(x,x′) + E k(y,y′) − 2 E k(x,y)

Conformal test martingales

  • Give each new point a nonconformity score (for example |AR residual|), then rank it among the historical scores to get a p-value. With no change, the p-values are uniform.
  • A betting function turns these p-values into a running statistic that grows when the p-values stop looking uniform.
  • This relies on exchangeability (roughly, the data's order not mattering), so use residuals rather than raw autocorrelated values.
pₜ = (#{j : sⱼ ≥ sₜ} + 1) / (n_H + 1)    # deterministic ties
f(p) = ε·p^(ε−1),  0 < ε < 1             # betting function
Cₜ = max(0, Cₜ₋₁ + log f(pₜ))            # conformal CUSUM

E-values

  • An e-value is a non-negative statistic whose expected value is at most 1 when there's no change. Multiplying them over time gives a test martingale Mₜ.
  • Ville's inequality bounds the false-alarm probability. E-detectors are CUSUM and Shiryaev–Roberts built from these.
P( supₜ Mₜ ≥ 1/α ) ≤ α     # Ville's inequality
§11

Neural models and synthetic data

Advanced
  • GRU / RNN. hₜ = GRU(hₜ₋₁, inputₜ) costs O(1) per step: a learned running state, like a CUSUM it figured out by itself. Train with binary cross-entropy on every yₜ. Inputs can be zₜ, zₜ², AR residuals and detector values.
  • Train with truncated backpropagation through time (BPTT) on sequences up to 1,000 steps. Optionally warm the hidden state up on the end of the historical segment.
  • AutoCPD (Li, Fearnhead, Fryzlewicz, Wang, 2024) shows that small networks can represent CUSUM-type tests, so they can learn them from data. They beat CUSUM when the noise is autocorrelated or heavy-tailed.
  • Synthetic breaks. Split a break-free historical segment into a pseudo-history and a pseudo-online part. With probability ½, insert a change at a random τ: shift the mean, scale the variance, change the AR coefficient, or switch the noise distribution. This gives unlimited labelled data with realistic noise.
  • Amortised inference. Pretraining on many synthetic tasks, as TabPFN and regime-change transformers do, lets a model infer at test time without fitting. It's frontier work and expensive to run here.

TrapFor deterministic neural inference, run on CPU, call torch.use_deterministic_algorithms(True), and fix all seeds.

Self-check

τ = 37. What are the labels at t = 36 and t = 37?

0 and 1. The break step itself counts as post-break.

Why does outputting t / T score exactly 0.5?

At each step, every series gets the same score, so the AUC at each step is 0.5, and so is the weighted average.

Why monitor AR residuals instead of raw values?

Autocorrelated noise makes runs of high or low values look like breaks. Whitening makes the online points roughly independent, so CUSUM, rank tests and conformal p-values behave as intended.

Why split cross-validation folds by series?

Steps from the same series share almost all their features. A random split puts near-copies in both train and validation, so the CV score comes out too high.

The variance doubles but the mean stays put. What reacts?

The running mean of z² (or a CUSUM on z² − 1) rises above 1. A mean-only EWMA, like the baseline's, barely moves.

Why can a test of "history vs all online points" miss a late break?

Hundreds of pre-break online points dilute a few post-break ones. CUSUM resets, windows forget old points, and GLR searches over split points, which avoids this.

Glossary

ARL
Average run length: expected steps until a false alarm when nothing has changed.
EDD
Expected detection delay after a real change.
KL divergence
How distinguishable two distributions are. It sets the best achievable detection delay.
Hazard
Prior probability of a change at each step (Bayesian online change-point detection).
Run length
Time since the most recent change.
Nonconformity score
How unusual a point looks compared with the reference data.
Exchangeable
The joint distribution doesn't depend on the order of the data. Conformal methods need this.
e-value
Evidence statistic whose expected value is at most 1 under no change. Large values are evidence of a change.
Whitening
Removing autocorrelation, for example by taking AR residuals.
lambdarank
A LightGBM objective that optimises ranking within groups. Here a group is a time step.
Leakage
When information unavailable at prediction time (future points, the same series) gets into training or validation.
